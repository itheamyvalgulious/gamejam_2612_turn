# ACT // 四足刀客 — 3D 动作游戏 demo

现行关卡由仓库的 [统一 TURN 工程](../../../../README.md) 启动。ACT 地图负责霓虹窄巷和雨夜广场；灯墙之厅的源码位于 [shadow_chamber](../shadow_chamber/README.md)，使用折相的战斗控制器。以下开发记录中的旧敌人与测试数据对应原型时期。

```bash
python main/tools/prepare_game.py
godot --headless --path main --import
godot --path main
```

Godot **4.7.2** / Forward+，全部资源运行时程序化生成（零外部模型 / 零贴图）。
主角和敌人共用本工程 `src/vesper/` 的程序化机体模型。赛博朋克着色器的相关实验在 [城市地图](../../maps/t1_city/ds41-1017-max/)。

## 尺度约定（2.5 m 机体）

整套美术（机甲 / 街道 / 房间 / 灯光 / 特效）共用同一个**世界单位**：**1 单位 = 0.547 m**。
所以机甲从脚底到天线 4.57 单位 = **2.50 m**，小怪同高，大怪 ×2 = **5.00 m**；
场景也按同一把尺子读：窄巷 22 × 37 m、广场 46 × 46 m、灯墙厅 66 × 66 m（天花 10.4 m）、低位壁灯 0.98 m。

- `~` 面板与 `user://actdemo_params.json` 里**每一个长度都是真实米**（`m` / `m/s` / `m/s²`）。
- 仿真内部仍用世界单位（几何、特效、音频距离都不必改），换算只在 `src/core/units.gd` + `P.getf()` 一处发生；
  `P.getm()` 拿到的就是存档里的米。改参数时不要手乘 0.547。
- 于是面板读数都是真实尺度：跳跃 **1.50 m**（重力 **10 m/s²**，滞空 1.09 s）、冲刺 **3.00 m**、
  小怪挥刀 3.39 m、弹反半径 3.83 m、第三人称镜头 7.11 m。
- `tools/probe_scale.gd` 会把这几条实测一遍（机体高度 / 跳跃顶点 / 冲刺位移 / 六个攻击时间轴）。

## 核心机制：视线

三关共用一条规则——**只按相机画面判定，零余量，敌人必须完全离开画面才算"看不见"**。

| 敌人 | 你看着它时 | 破解 |
| --- | --- | --- |
| **小怪** | 你的刀砍上去 **100% 被格挡**（打铁火花、不掉血） | 侧斩 / 回身斩 / 回旋斩，用画面外的刀弧打 |
| **远程怪** | 弹反瞬间正对它 → 它补射一支**拦截箭**，把你弹回的箭在空中打掉 | 不看它弹反 → 弹回的箭原路命中它 |
| **大怪** | **立即激光秒杀**（冷却与预警可调） | 全程不直视：靠四面墙上的**影子**（含你自己的）读它的位置与出招 |

### 为什么默认第一人称

视野规则是"按相机画面、零余量"，而**第三人称环绕相机在几何上不可能把近处敌人移出画面**：相机在玩家背后 D 米、敌人距玩家 d 米时，敌人在画面里能偏离视轴的最大角度只有 `atan(d/D)`。D=7.1 m、d=3.3 m 时上限约 25°，远小于 16:9 下 50° 的半视场——所以第三人称下近身小怪永远"看得见"，永远格挡。

因此：**第一人称是战斗视角**（相机在头部，d/D → ∞，转头 100° 就能把敌人甩出画面），**第三人称是按 `V` 切换的观察视角**（看全身、看清场地；这一关的远程/大怪依然能用"转身 180° 把它甩出画面"来打）。HUD 会在有敌人在画面里格挡时直接提示。

## 三关

| 关 | 场景 | 敌人 |
| --- | --- | --- |
| 1 | **霓虹窄巷**（冷紫立面 + 湿沥青霓虹倒影 + 雨 + 跨巷钢桁架） | 1 小怪 |
| 2 | **雨夜广场**（青绿商圈、亮窗楼群、霓虹环柱、掩体） | 3 小怪 + 1 远程 |
| 3 | **灯墙之厅**（66 × 66 m 大平厅 + 四面平整大墙 + 每墙一盏低位壁灯） | 1 大怪（×2 体型） |

第三关的墙影走 **GPU 投影幕布**（`src/fx/wall_shadow.gd` + `gfx/wall_shadow.gdshader`）：

- 每台角色（大怪 **和玩家**）的**真实网格**按骨骼节点合并成一组影子网格（约 30 块 / 2.3 万三角形，含刀、腿法、天线），只放在投影层（layer 2），**不是包围盒代理**；
- 墙外一台**正交相机**把影子层 1:1 投进一张 2048 宽的透明底遮罩（SubViewport），墙面前 3 cm 的透明 quad 按同一套投影采样；
- 正交投影与朝向无关（沿轴投影得到的二维集合从正面看/背面看完全一样），所以**法线相反的墙共用同一张遮罩** —— 四墙厅只要 2 个遮罩视口。

于是剪影天然连续（不会出现「零件之间的断口」），**四面墙每帧都有场上所有人的影子**（不会某面墙突然没有），玩家自己的影子也一直在墙上（第一人称隐藏机身时也在，因为影子网格是独立的 top_level 副本）。1:1 意味着影子的横向位置就是角色的横向位置：四面墙合起来是一张准确的位置图。

第三关是**背向入场**：出生点在南墙前 10.9 m、背对大怪，开场横幅期间大怪不开激光（切关那一帧相机已瞬间对位到新出生点）。所以第一眼看到的是它投在墙上的影子，转身才是「看见即死」的正面遭遇；对战空间 66 × 66 m。

## 技术要点

### 0. 攻击动作（程序化，不是关键帧）
左右横斩与后刺不是动画关键帧，而是**按方位角直接驱动刀**（`rig.force_swing(a0, a1, {...})`）：
- 刀身被摆成**水平外伸**，单手（左手松开，`offhand` 把左臂解算到体侧待机位）
- 挥砍弧 = 方位角从 a0 扫到 a1，与判定窗口严格同步（判定窗口 = 刀真正在动的区间）
- 实测有效距离：四个方向都是 **3.0–3.6 m**（原关键帧动作只有 ~2.5 m，且正后是空的）

覆盖矩阵（敌人 2.5 m 处，FPS 模式）：

| 敌人方位 | 正前 | 左 | 右 | 后 |
| --- | --- | --- | --- | --- |
| 0° | ✓ | ✓ | — | — |
| ±90° | ✓ | ✓ | ✓ | ✓ |
| ±135° | — | ✓ | ✓ | ✓ |
| 180° | — | ✓ | — | ✓ |

### 0b. 方向斩的一个坑
方向斩只旋转**躯干 yaw**（武器挂在躯干下会跟着转）。如果把 `wpx/wpz` 再单独旋转一次，偏转会叠加成 180°（回身斩变正前斩）——这个 bug 是靠"四个方向各放一个敌人 + 反方向对照"的自测才抓出来的。

### 1. 剑的真实网格碰撞（不是胶囊/射线）
启动时把剑的每个 `MeshInstance3D`（刀身/辉光/血槽/护手/柄，共 25 个网格）的顶点从 `ArrayMesh` 里读出来，变换到武器空间后按 Y 分 30 桶，算出**圆盘剖面** `[{y, r}]`。
每一帧把圆盘中心在「上一帧→当前帧」之间连成扫掠线段，与目标胶囊做**线段-线段最近距离**检测（`src/core/hitgd.gd`），所以：

- 挥砍命中是刀的真实形状（含 1.45× 的躯干缩放）；
- 高速挥砍不穿模（圆盘中心这一帧的位移本身就是一条扫掠线段，线-线最近距离不会漏）；
- 箭矢被弹反用的是同一套几何（线段扫掠 vs 圆盘），不是"球形格挡范围"。

**敌人受击面不是一根躯干胶囊**：`MechRig.hit_parts()` 每帧按真实关节坐标生成 24 个判定件 —— 骨盆 / 胸 / 背包 / 头 / 肩甲×2 / 四条腿(股骨+胫骨+足) / 双臂(上臂+前臂+拳)。玩家挥砍与弹回的飞行物都用 `Hit.sweep_blade_parts` / `sweep_sphere_parts` 逐件求最深接触，所以**打腿、打手、打肩甲都算命中**；件的半径只有关节粗一圈，躯干之间/腿之间的空档不会误判。扫掠线段一帧只算一次并先用 AABB 剔远件，30 圆盘 × 24 件实测 ~0.7 ms。

### 1b. 格挡：读招 → 机械臂路径 → 剑挡剑（`src/game/intercept.gd` + `src/vesper/blade_path.gd`）

右键不再"瞬间举刀 + 球形判定"，而是三件事：

1. **读招**：敌人挥砍的姿势是闭式动画（关键帧 + 方位角驱动），所以 `mech_rig.predict_weapon_xf(t)` 能直接解出**未来任意时刻刀在世界里的位姿**（含前冲位移）。自测里断言 `predict(现在) == 真实位姿`，偏差 0.00 m —— 这是"读招"而不是猜。
2. **落点与刀轴**（`Intercept.melee_threat` / `Intercept.projectile_threat`）：在整段判定窗口里往前扫 + 二分，找**刀锋最早进入「身体 + 让出距离」的那一刻**，把落点定在那一刻的刀身上（机体胶囊之外 —— 它还没打到你）。刀轴取「敌人刀的运动方向 × 来向」，也就是**横在它的来路上**。飞行物用航路求交（解一元二次），落点取「离身体够近但还没打到」的那一段。
3. **机械臂路径**（`BladePath`）：从**当前真实刀位姿**到目标位姿规划一条过渡 —— 位置走二次贝塞尔（控制点把刀往体外撑，手臂绕开胸腔）、朝向走四元数最短弧、躯干（腰环）偏航同步插值；时长 = 刀柄路程 / 出刀速度（`parry.plan_speed`），上限由威胁的到达时间决定。两条手臂的两骨 IK 每帧跟到刀柄上，所以**「刀的路」自动就是「机械臂的路」**，不需要单独解关节角。

判定仍然只认真几何：`Hit.blade_vs_blade_swept` 把两把刀这一帧各自的扫掠体（prev→cur 插值采样）两两求最近接触，`gap ≤ 0` 才算架住 —— 快刀单帧能扫 1.1 m，只比"当前一瞬间"会漏判。架住的效果：**不调用 `hurt`（免伤）+ `parry.block_knockback` 把人推开 + 顿帧 + clang/冲击环/HUD**。

窗口与冷却照旧：`parry.window` 0.24 s / `parry.cooldown` 0.35 s，决定了"什么时候能把刀送出去"；只要刀还在架着（`is_guard_up()`：规划中 / 等它撞上来 / 收势中），它挡在那儿就挡得住。窗口过去后只要威胁还在，规划会继续跟招（不会把架好的刀提前收回去），威胁消失 `parry.pose_time` 之后才收势。

真实场景实测（第一关、真 AI 小怪、站在它面前）：在它起手后的 0.00–0.50 s 之间任意时刻按右键都能架住（12 个采样点里 11 个成功，唯一失败的是在刀已经贴脸前 0.03 s 才按）；`qa_parry` 里正对 / 侧身 / 背对 / 提前半秒按 全部覆盖。

### 2. 攻击时序与动画解耦
每个攻击（4 方向斩 / 重斩 / 回旋斩）都有独立的 `时长 / 前摇 / 后摇` 参数，**判定时长 = 时长 − 前摇 − 后摇**。
动画只提供动作形状：用三段线性 warp 把参数时间轴映射回动画相位（`_warp_time`），相位基准取动画自己的**刀光窗口**（刀真正在动的区间），所以无论你把手感调多快多慢，挥砍弧永远落在判定窗口里。前冲距离、刀光拖尾、命中停顿同样按 warp 后的时间驱动。

### 3. 声音：全部是算出来的，而且用来定位
没有任何音频文件。每个音色由 `src/audio/synth.gd` 用**振荡器 / 白噪声 → 双二阶滤波器（中心频率可随时间扫描）→ 分段包络**逐样本渲染：

| 声音 | 物理建模 |
| --- | --- |
| 脚步 | 足垫触地的短促宽带"咔" + 伺服电机下滑音 + 极轻的低频重量感（低频占比 0.05，不再是鼓） |
| 挥剑 | 钢刃切空气的高频"唰"：带通 850→4200→… 扫频 + 刃口哨音 + 高频沙沙（低频占比 0.01） |
| 箭啸 | 窄带自激（1.75 kHz，Q=7）+ 弱泛音，做成无缝循环，挂在箭的节点上跟着飞 |
| 箭命中 | 高频瞬态 + 低频下扫 |
| 打铁 / 弹反 | 钢件高频非谐模态（基频 1850 / 2600 Hz）+ 极短高频瞬态（低频占比 0.02，不是桶鼓） |
| 刀气 / 激光 / 重击 / 击破 | 噪声扫频 + 次低频下扫 + 噪声尾（重击还有一层低频轰鸣） |

空间化不是丢给引擎摆位，而是 `src/audio/audio.gd` 自己做**双耳混音**（逐样本，立体声输出）：

| 线索 | 实现 |
| --- | --- |
| 左右（ILD） | 等功率摆位，`L=√((1-pan)/2)`，`pan = dir·右耳轴` |
| 左右（ITD） | 远耳延迟最多 ~0.65 ms，短历史缓冲线性插值（同一侧的两耳相位差也是定位线索） |
| 头部阴影 | 远耳一阶低通，越偏侧越闷 |
| 前后 | 背后声源整体变闷 + 轻微衰减（近似耳廓方向滤波），所以**正前和正后听起来不一样** |
| 距离 | 所有音色先归一化到同一响度，再由 `(4/(4+d))^1.25` 衰减 + 空气吸收低通决定远近（d 是世界单位，4 u = 2.19 m）：**1.1 m −4 dB → 11 m −20 dB → 33 m −30 dB**，低通同时从 0.39 降到 0.075（越远越闷）。所以箭飞近时又响又亮 |
| 遮挡 | 视线被墙挡住（用关卡墙段做 2D 视线判定）→ 更闷更小 |
| 空间残响 | 总线上一组 Schroeder 混响（2 梳状 + 1 全通，街巷/大厅的短混响），`audio.reverb` 可调 |
| 多普勒 | 按声源/听者径向相对速度改播放速率（世界单位下的声速，与音速同比例） |

性能：混音 12 kHz / 每 64 样本更新一次空间参数 / 只有最响的 6 个声部走完整处理，实测 9 声部同时 3.6 ms、日常 1.5–2.5 ms。
`~` 面板的「音频」组可以单独调总音量 / 脚步 / 挥剑 / 箭啸音量、最远可闻距离、空间化开关、遮挡开关、多普勒强度。

### 4. 第一人称手持武器
第一人称**不是**把世界模型里那把 1.3 m 刀身的大刀塞进画面（那样又大又爆白），而是挂着相机下的**独立手持模型**
（`src/game/fp_viewmodel.gd`：0.5 m 等比缩小的刀 + 两段前臂），姿态由攻击相位驱动——
左右横斩时刀会跟着方位角从画面右侧扫到左侧，弹反时刀瞬间指向来袭方向，走路还有轻微摆动。
想对比的话把 `cam.first_show_weapon` 打开，就会看到世界模型那把大刀（默认关）。

### 5. 回放（Del）
每帧把**所有机甲关节的世界变换**（玩家 + 最多 4 个敌人，每人 24 个关节，各存位置+四元数+缩放）
+ 飞行物位置写进一个 20 秒的环形缓冲（约 7 MB），按 `Del` 变成第三人称实时重放：模拟暂停，只把录到的变换写回节点，
鼠标可以自由环视。录制的是"结果"而不是"输入"，所以不受模拟里任何时序/随机影响，轨迹与实际完全一致
（自测：实际走过 25.94→14.28，回放写回 26.0→14.36，逐帧比对 0 次不一致）。

**缩放必须一起录**：`torso ×1.45` / `head ×1.42` / 大怪 `rig ×2` 都在节点缩放里，只写「位置 + 旋转」
会把机体压成一根细柱子（`qa_replay` 逐步比对位置/旋转/缩放，专门盯这个回归）。

排查打击判定时这个最直接——刀身扫掠、敌人被格挡的位置、视野判定发生在哪一帧，全都能倒回去看。

- 墙影开销：CPU 每帧只同步 60 块影子网格的位姿（实测 0.1–0.4 ms，重建几何在关卡开始时一次）；
  GPU 是 2 个 2048 宽遮罩视口 + 4 块墙面 quad（GTX 1650 / 1280×720 实测约 +2.8 ms，
  需要省帧率时把 `mask_hz` 设 2 → 两个方向轮流 30 Hz，约 −0.7 ms）。

## 网页版

- 构建：`./web/build_web.sh`（自动把渲染器临时切成 `gl_compatibility`，导出后还原 `project.godot`，所以桌面版仍是 Forward+）。产物在 `build/web/`（wasm 39 MB + pck 3.7 MB，pck 里 4.9 MB 是 CJK 字体回退链）。
- 桌面版：`./web/build_web.sh build_all` 额外导出 Windows(x86_64，单文件 exe，pck 已内嵌) 与 macOS(universal，`.app` 打成 zip) 到 `build/win/`、`build/mac/`（渲染器已还原成 Forward+）。macOS 包未签名，首次打开需右键 → 打开（或 `xattr -cr ACT*.app`）。
- 伺服：`./web/serve_web.sh` → **http://127.0.0.1:16374/**（`web/serve_web.py`，正确 MIME + COOP/COEP）。同一端口下 `/win`、`/mac` 就是两个桌面版的下载链接（`./web/build_web.sh build_all --serve` 可一次构建+伺服；`./web/build_web.sh serve` 只伺服不重建）。
- Web 用的是 Compatibility(WebGL2) 渲染器：没有 SSAO/SSR，泛光弱一些，其余一致；音频（WebAudio worklet）在浏览器里需要先点一下页面才会出声。
- 每次改完代码要重新 `./web/build_web.sh`（桌面版要跟着更新就用 `build_all`）。

### 打不开 / 报 "Secure Context" 怎么办

Godot 的网页壳默认要求浏览器处于**安全上下文**（`https://` 或 `http://localhost` / `http://127.0.0.1`）。
如果你是通过**局域网 IP 或网关**（例如 `http://10.82.90.210:16374/`）打开的，浏览器会判定为非安全上下文 → 报
`The following features required to run Godot projects on the Web are missing: Secure Context`。

本项目是**非线程构建**（不用 SharedArrayBuffer），也不读麦克风/手柄，所以非安全上下文完全可以用。因此
`web/build_web.sh` 在导出后会做一次后置补丁，把这条检查**降级成 console 警告**，于是：

| 地址 | 说明 |
| --- | --- |
| `http://127.0.0.1:16374/` | 本机 |
| `http://10.82.90.210:16374/` / `http://172.16.0.103:16374/` | 走网关（已配置好 16374 → 127.0.0.1:16374） |
| `https://127.0.0.1:16375/` | 可选：`./web/serve_web.sh --tls --port=16375`，自签名证书的安全上下文 |

但仅仅跳过这条检查还不够，第二个坑紧随其后（见下）。

**旧页面会被缓存**，改完/重新导出后请 `Ctrl+Shift+R` 硬刷新（或开无痕窗口）。

### 报 `Cannot read properties of undefined (reading 'addModule')` 怎么办

`AudioContext.audioWorklet` 是 `[SecureContext]` 接口：`http://` + 局域网 IP 时这个属性**压根不存在**。
而 Godot 的 `GodotAudio.init()` 里是无条件写 `ctx.audioWorklet.addModule(...)`，于是：
跳过「Secure Context」检查 → 引擎继续跑到音频初始化 → 在这里抛 `TypeError` → 整个页面白屏（wasm 初始化中断，游戏永远不会开始）。

修法：`web/build_web.sh` 导出后打了第二个补丁，把它换成
`ctx.audioWorklet ? ctx.audioWorklet.addModule(path) : Promise.resolve()`。
没有 worklet 时引擎自己会退到 `ScriptProcessorNode` 音频驱动（控制台会有一条 deprecated 警告，正常）。
想要真正的 worklet 音质就用 `https://`（安全上下文）打开。

### 中文字全是方块

Godot 内置默认字体（Noto Sans 子集）**没有汉字**。桌面版之所以正常，是 Godot 4.3+ 会回退到系统字体（fontconfig）；
浏览器里没有系统字体可回退，于是全部变豆腐块。

修法：字体已经打包进项目，并在 `project.godot` 里设成全局默认字体：

```ini
[gui]

theme/custom_font="res://assets/fonts/ui_font.tres"
```

`assets/fonts/ui_font.tres` 是一条回退链（FontVariation）：

| 字体 | 作用 | 大小 |
| --- | --- | --- |
| `OpenSans-Regular.ttf` | 拉丁字母 / 数字（与内置默认字体观感接近） | 0.2 MB |
| `DroidSansFallbackFull.ttf` | 汉字（注意：这个字体**故意没有拉丁字形**，所以不能单独用） | 4.0 MB |
| `DejaVuSans.ttf` | 符号（`⚠`、`·` 等） | 0.7 MB |

三者并集覆盖了项目里所有 1160 个非 ASCII 字符（含注释里的），`ThemeDB.fallback_font` 和所有 `Control` 都走这条链，
桌面版和网页版字形一致。pck 因此从 0.7 MB 涨到 3.7 MB。

## 已知限制

- 主角与敌人一刀必杀（`rules.one_hit_kill` 可关、`rules.player_hp` 可调），是 demo 手感而非平衡。
- 墙影是 1:1 正交投影：横向位置准确，但影子不随距离缩小（纵深要靠对面那面墙的影子一起读）。
- 敌人 AI 是规则驱动的有限状态机（无寻路/无回避），L2 三个小怪会直线贴脸。
- 第三人称下近身小怪无法被"看不见"（见上面的几何说明），这时请按 `V` 切第一人称。
- 第四关不存在：第三关清完显示「全部通关」。
