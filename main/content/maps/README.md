## 三家的风格差异（一句话）

- **deepseek-v4.1-flash-1017**：工程组织最规整、出片率最高、最擅长空间叙事；对「细节不够」的反馈响应最好；外壳造型偏保守。
- **qwen-3.8-max**：造型野心最大（扭转塔 / cosh 冷却塔 / 摩天轮 / 天际铁路 / 扇面索斜拉桥），参数化程度高；但着色器质感长期偏弱，光照标定慢，早期容易在思考里空转。
- **swe-2-high**：调试纪律最强（`--only/--mark/--nolight/--noao/--noshell/--dump`、`--check-only` 逐文件校验、shader 编译 harness），会自己派子代理并行化模块；外壳剪影最像「船」。代价是**免费配额每小时一档**（一次对话就烧光），且视觉判断力最弱——它的每一格都是「bug 修得干净、画面立不起来」，需要外部逐张指出问题。

### swe 的三格（原型级）

- **飞船（最好的一格）**：279 m 主线 / 11 功能区 / 约 99k 三角 / 895 ms。修掉门扇太薄嵌进墙、`METALLIC` 反射黑星空、`quad` 绕向导致整面被剔除、`plant` 卡片拿到米制 UV、舰首整面墙缺失导致星空漏光。
- **地形**：10 km² 三群系。关键根因：三角形绕序全反（透过地表看天空）、`COLOR` varyings 被驱动丢弃（splat 权重改走 `CUSTOM0`）、水面顶点 y 与 carve 地形不同步。树冠最终改成「7 区 × 8–26 个小 lobe」的碎簇才摆脱低模感。
- **城市**：10 km² / 1142 栋 / 五区 / 五个地标全有。噪点根因链最完整：连续 UV 喂 hash、`p*123.34` 大坐标精度退化、`fwidth(cell)` 在掠射面自身抖动、窗格 `across` 取到深度轴、`glass` 与 `wall` 双绘叠印。

## 十四个踩过的坑（按价值排序）

1. **着色器编译失败不会中断渲染，只会静默输出旧图/默认材质**。本项目两次栽在这上面：`waterfall.gdshader` 的 `strand_phase` 未声明 → 水幕变成半透明帘幕；`wall.gdshader` 的 `r2` 未定义 → 走廊渲染一直在用旧 PNG。**验收必须核对 PNG 的 mtime**。
2. **单一频率是程序化材质的头号通病**。糊和砂纸是同一个病：缺少 1 mm / 10 cm / 1 m 三档同时存在，以及「形」（棱、缝、层理）而非「纹」。两个地形模型都反复栽在这里。
3. **`fwidth()` 屏幕足迹衰减**是消除近景摩尔纹的通用解：`lod = clamp(max(fwidth(uv))*k, 0, 1)`，细节强度乘 `(1-lod)`。
4. **`Environment.volumetric_fog` 的 froxel 网格 + 时域抖动**会在全屏叠加一层规则网纹（连天空都有），且极难误判为「材质问题」。关掉环境体积雾、只留距离雾/FogVolume 即可。
5. **`METALLIC` 数值过高会把未受光面反射成纯黑**（无探针/SSR 时反射黑星空），是「整面墙死黑」的常见原因。opaque 材质压到 0.04–0.12。
6. **`SurfaceTool` 手工写进的法线不参与光照**，必须 `generate_normals()`。
7. 天空 shader 入口是 `sky()`，`EYEDIR` 不可用 → 用 `INV_PROJECTION_MATRIX` 反推视线。
8. **背面剔除绕向与常规相反**，手写 `ArrayMesh` 容易整面消失；`cull_disabled` 是便宜稳妥的兜底。
9. `ArrayMesh` 属性数组类型收紧，`PackedVector3Array` 与 `Array` 混用会崩。
10. **单张覆盖全城的巨 quad**，`varying` 从四角（≈4 km）插值会把雾/光照算错 → 必须分网格。
11. **掠射角镜面反射天空色**会在地面产生「薰衣草脏斑」→ 地面 `SPECULAR=0`。
12. **水面网格的 clamp 错误**会把水潭折成一块 200 m 大板横在场景里（`_pool()` 把上游顶点钳到溢流口高度）。
13. **`plant` 卡片拿到米制 UV**（工具函数只给 `u_*` 材质单位 UV）→ 绿植渲染成纯白十字面片。
14. **误生成的几何比渲染 bug 更难查**：swe 用逐材质 `--hide` 才定位到走廊里横穿的两条轨与一根栏杆（kit 层缺「净空体」闸门）。

## 对「AI 生成游戏地图」的判断

- **能给的**：可在引擎里实时跑、尺度真实、结构合理、带分区与 LOD 的场景，以及一整套能直接改的代码（这批交付全部可运行）。
- **不能给的**：一次到位的美术完成度。9 格里有 6 格经历 2 轮以上外部质检才到「能看」，且各自仍有明确短板。
- **成本结构**：建模不是瓶颈（生成 1.6–3 s），**瓶颈是光照/材质标定与观感验收**。每个模型都把 30%–60% 的时间花在「渲染 → 看图 → 改光照」上。
- **人的位置**：子代理无法自己判断「这像不像石头/水/墙」。它们能照配方实现结构（Voronoi 是照指令加的），但配方本身要给对，验收必须由人看图。这轮 9 格里有 4 格的突破来自外部指出具体问题（整墙死黑、froxel 网纹、珠帘水幕、叶片棋盘格）。

## 运行方式

每个目录都是独立 Godot 工程：

```bash
cd t1_city/ds41-1017-max && ./run.sh                # 交互（首次运行自动导入）
cd t3_spaceship/qwen38-max && ./run.sh -- --capture # 重出图
```

键位、参数与已知限制见各目录 `README.md`。
